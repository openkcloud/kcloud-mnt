01한줄 요약

"UI는 완성, 백엔드는 목(mock)" 구조입니다. 실제 Kubeflow 연동 지점이 코드 주석으로 명확하게 표시되어 있어, 우리 팀의 실질적인 개발 범위는 CMP 백엔드 API + Kubeflow Notebook Controller 연동이며 프론트엔드는 지정된 교체 지점만 갈아끼우면 됩니다.

  • NotebookResource 타입이 Kubeflow Notebook CRD에 직접 매핑 — namespace=Profile, rebellions.ai/atom 등 K8s 리소스 키, PVC 마운트, connectUrl, connectMode: "live" | "mock"
  • fetchNotebookConnect(): "실제 구현 시 이 fetch 한 줄만 살리고 목 블록 삭제" 주석 포함 → GET /api/v1/notebooks/{id}/connect (OAuth2 Proxy 쿠키 포함)
  • notebookAction(id, start|stop|restart|delete) → POST /api/v1/notebooks/{id}/{action}

04IDE 화면 구조

(fullscreen)/notebooks/[id]/ide/view.tsx — CMP 셸이 Code Server를 iframe으로 감싸는 구조:

┌ Top Bar (CMP) ── 가속기·리소스 배지 + 재시작/정지 ──┐
├──────────┬──────────────────────────────┬──────────┤
│ Side     │  iframe(connectUrl)          │ 가속기   │
│ Panel    │  = 실제 Code Server (live)   │ 모니터   │
│ (CMP)    │  = mock preview     (demo)   │ (CMP)    │

핵심 설계: Kubeflow가 실제 설치되면 iframe src만 교체하면 되고, CMP 셸(헤더·사이드패널·가속기 모니터)은 그대로 유지됩니다.

05실제 구현 가이드 (notebook-api.ts 하단 주석에 명시)

  1. CMP 백엔드 (FastAPI 등): POST/GET/DELETE /api/v1/notebooks, GET …/{id}/connect (connectUrl + Set-Cookie 발급), POST …/start·stop — annotation kubeflow-resource-stopped 토글
  2. Kubeflow Notebook Controller v1.10.0 standalone 설치 (kubectl apply -k github.com/kubeflow/kubeflow/components/notebook-controller/…)
  3. Notebook CRD 생성 — resources.requests에 rebellions.ai/atom: "2" 같은 가속기 리소스 키
  4. Istio VirtualService — /notebook/{ns}/{name}/ prefix를 노트북 Service로 라우팅 (iframe용)
  5. oauth2-proxy + JWT — CMP JWT를 Kubeflow oauth2-proxy 쿠키로 변환해 iframe 인증 자동 통과
  6. 가속기별 Code Server 이미지: openkcloud/codeserver-rbln:1.4.0 · codeserver-cuda:12.4 · codeserver-pim:0.7
