STEP 0 — 시작 인사 1분 · 포털 첫 화면

화면: 포털 첫 화면을 띄워놓고 시작

"저희가 국책과제에서 맡은 건 'AI 노트북'입니다. 쉽게 말해 연구원들이 AI를 만드는 온라인 작업실이에요. 2주 전엔 화면 그림만 있었는데, 지금은 사무실 컴퓨터 3대를 연결해서 진짜로 작동하는 시스템을 만들었습니다. 지금부터 신입 연구원이 AI 하나를 만들어 서비스로 내놓는 과정을 처음부터 끝까지 보여드리겠습니다."

STEP 1 — 팀별로 장비를 나눠 쓰는 화면 2분 · Profiles 탭

클릭: AI 개발환경 → Profiles. 카드의 게이지(막대)를 가리키기

"먼저 회사 아파트 관리사무소 같은 화면입니다. 팀마다 '작업 공간'을 배정하고, 컴퓨터 자원을 얼마나 쓸 수 있는지 정해줍니다. 이 막대가 지금 이 순간 각 팀이 쓰고 있는 양이고요 — 정해진 몫을 넘으면 시스템이 알아서 막아줍니다. 나중에 '쓴 만큼 요금을 매기는' 클라우드 사업의 기초가 되는 부분입니다."

팀 카드 3장, 사용량 막대가 실시간으로 표시됨

STEP 2 — 1분 만에 개발 작업실 만들기 3분 · Notebooks 탭 ★하이라이트

클릭: Notebooks 탭 → 아래쪽 카탈로그에서 "Kubeflow Code Server (Python)" 카드 클릭 → 이름 demo-ceo 입력 → 생성 → 목록에서 "Running" 되면 "연결" 클릭

"연구원이 개발용 컴퓨터를 신청하는 장면입니다. 예전엔 장비 신청서 내고 며칠 기다렸다면 — (생성 클릭) — 지금 시스템이 작업실을 준비하고 있고요… (Running 뜨면) 1분 만에 끝났습니다. '연결'을 누르면 — 보시는 것처럼 브라우저 안에 개발 프로그램이 통째로 뜹니다. 연구원 개인 컴퓨터가 좋을 필요가 없어요. 어느 컴퓨터에서든 접속만 하면 고성능 장비로 일할 수 있는 겁니다."

"그리고 화면 오른쪽을 보시면 — 이 작업실이 쓰고 있는 장비 상태가 실시간으로 나옵니다. GPU가 얼마나 일하는지, 온도가 몇 도인지. 학습을 돌리면 이 숫자가 확 올라갑니다."

30초~1분 안에 Running → 연결하면 개발 프로그램 화면 + 우측 GPU 실측 수치(3초마다 갱신)

STEP 3 — 보안도 챙겼습니다 1분 · 시크릿 창

클릭: Ctrl+Shift+N (새 비공개 창) → 방금 그 작업실 주소 붙여넣기 → 차단 화면 확인 → 창 닫기

"그런데 이 작업실, 주소만 알면 아무나 들어올 수 있을까요? 로그인 안 한 창에서 들어가 보면 — 이렇게 잠겨 있습니다. 연구원들이 만드는 코드는 회사 자산이니까, 허가받은 사람만 들어올 수 있게 해놨습니다."

"🔒 인증이 필요합니다" 잠금 화면

STEP 4 — 반복 작업은 자동으로 2분 · Pipelines 탭

클릭: Pipelines → dm-code-train 선택 → 상단 단계 그림(5단계) 가리키기 → "새 실행" 클릭 → 스케줄 탭 열어 daily-retrain 예약 보여주기 (결과는 STEP 4-C에서 확인)

"AI를 가르치는 일은 '재료 손질 → 요리 → 맛보기' 같은 여러 단계를 반복하는 일인데요, 그 과정을 레시피로 등록해두면 버튼 하나로 전 과정이 자동으로 돕니다.

(화면 위 그림 가리키며) 보시면 이 파이프라인이 어떤 순서로 도는지 그림으로 나옵니다 — 데이터 준비 → 학습 → 성능 평가 → 포장 → 서비스 반영, 다섯 단계입니다. 중요한 건 마지막 두 단계인데요, AI를 만들기만 하는 게 아니라 만든 즉시 현장이 쓸 수 있는 서비스로 자동으로 올려줍니다. 사람 손이 한 번도 안 들어갑니다.

(새 실행 클릭) 방금 눌렀고 지금 실제로 돌아가기 시작했습니다. 그리고 스케줄 탭을 보시면 — 매일 새벽 2시에 자동 실행되도록 예약해뒀습니다. 새 데이터가 쌓이면 밤사이 AI가 알아서 다시 학습하고, 아침엔 더 똑똑해진 AI가 현장에 올라가 있는 겁니다. 결과는 이따가 보겠습니다."

단계 그림 5개(prep→train→evaluate→package→deploy) · 실행 이력에 "Running" · 스케줄 탭에 daily-retrain

[말씀 도움] "이게 왜 대단하냐"고 물으시면 — 보통은 연구원이 학습을 돌리고, 결과를 확인하고, 파일을 옮기고, 서버에 올리는 일을 손으로 며칠 합니다. 그 전 과정을 버튼 하나에 76초로 묶은 것입니다.

STEP 4-B — 우리 현장 데이터로 만든 AI (실제 사례) 4분 · dm-train 노트북 ★최고 하이라이트

클릭: Notebooks → dm-train의 연결 → dm_train.ipynb 열기 → 3번 셀(샘플 이미지) 결과 보여주기 → 6번 셀(학습 결과 5줄) → 7번 셀(성적표) → dm_deploy.ipynb의 6번 셀(판정 테스트 6줄)

"여기서부터는 남의 예제가 아니라 저희 현장 이야기입니다. 부품에 찍는 DM코드 — 큐알코드 같은 산업용 코드인데, 잘 안 찍히면 판독기가 못 읽어서 다시 찍어야 하죠. 그래서 '이 코드는 읽힐까 안 읽힐까'를 미리 판정하는 AI를 제가 직접 만들어봤습니다.

(3번 셀 가리키며) 위가 잘 읽힌 코드, 아래가 실패한 코드입니다. 이런 이미지 5,651장을 넣고 — (6번 셀) 학습이 16초 만에 끝났습니다. 아까 그 4080 장비가 한 겁니다. 정확도 95%고요.

(7번 셀) 성적표를 보면 1,130장 중 1,073장을 맞혔습니다. (dm_deploy 6번 셀) 실제로 이미지를 넣어보면 이렇게 '실패 예상, 확신도 100%' 하고 답을 줍니다. 현장에 붙이면 촬영 즉시 재촬영하라고 알려줄 수 있는 겁니다."

성공/실패 이미지 비교 · 학습 로그 5줄(16초) · 정확도 94.96% · 판정 테스트 6건 전부 정답

STEP 4-C — 만든 AI를 서비스로 올리기 3분 · Serving 탭 ★마무리 하이라이트

클릭: 포털 → AI 개발환경 → Serving 탭 → dm-code-classifier 카드가 Ready인 것 확인 → "API 호출 테스트" 버튼 클릭 (판정 결과와 응답 시간이 바로 뜸) → (선택) 노트북 dm_serve.ipynb의 5번 셀 실행해 한 번 더 보여주기

"그런데 AI를 만들기만 하면 소용이 없죠. 현장 장비가 갖다 쓸 수 있어야 합니다. 그래서 — (Serving 탭 가리키며) 아까 그 파이프라인이 방금 이 서비스를 올려놨습니다. 제가 손으로 올린 게 아니라, 학습이 끝나자마자 자동으로 올라간 겁니다.

(API 호출 테스트 클릭) 실제로 불량 코드 사진 한 장을 보내보면 — 보세요, 0.05초 만에 판정이 옵니다. 이제 현장 검사 PC든, 웹 화면이든, 이 주소로 사진만 보내면 판정을 받아갈 수 있습니다.

정리하면 — 데이터를 올리고, AI를 만들고, 서비스로 띄우고, 갖다 쓰는 것까지 이 한 화면 안에서 다 됩니다. 이게 저희가 만든 AI 노트북입니다."

dm-code-classifier 카드 Ready · 판정 결과와 응답 시간(50~90ms) 표시

STEP 5 — 기계가 스스로 최적 설정을 찾음 2분 · Experiments 탭

클릭: Experiments → "Succeeded"로 끝난 lr-batch-hpo 실험 가리키기

"AI 성능은 요리로 치면 '불 조절, 소금 양' 같은 설정에 크게 좌우됩니다. 최적값 찾기는 원래 연구원이 밤새 이것저것 해보던 일인데 — 여기선 시스템이 알아서 여섯 가지 조합을 실험해보고 가장 좋은 답을 찾아냈습니다. 사람의 감이 아니라 데이터로 찾는 거고, 연구원은 그 시간에 다른 일을 할 수 있죠."

완료된 실험과 최고 성적(정확도 95.7%)이 표시됨

STEP 6 — 장비 성능을 숫자로 비교 2분 · 벤치마크 탭

"이 국책과제의 핵심이 '여러 회사의 AI 반도체를 골라 쓰게 하자'인데요, 고르려면 성능 비교표가 있어야겠죠. 그 표가 실제 측정으로 나옵니다. 저희 장비 두 대를 재보니 한쪽이 다른 쪽보다 3배 이상 빠르다고 나오네요 — 그럼 무거운 작업은 빠른 쪽에 시키면 되는 겁니다. 나중에 국산 AI 반도체(리벨리온)가 들어오면 이 표에 그대로 한 줄 추가됩니다."

장비 2종의 연산속도·처리 속도 실측 숫자 표

"마지막으로 제일 신기한 걸 보여드리면 — 저희 장비에는 지금 챗GPT 같은 진짜 AI가 하나 올라가서 서비스 중입니다. 질문을 보내보면… 보세요, 응답 속도 숫자들이 실시간으로 움직입니다. 질문받고 0.03초 만에 답을 시작하네요. 그리고 아까 돌려놓은 자동 학습 — 완료됐고요, 시스템이 '가운데 단계가 시간을 제일 많이 먹는다'고 색깔 막대로 짚어줍니다. 어디를 개선해야 할지 알려주는 거죠. 만들고, 가르치고, 서비스하고, 진단하는 것까지 — 이 한 벌 안에서 다 됩니다."

장비 상태 실시간 숫자 + AI 응답 지표 갱신 + 단계별 색깔 막대

03대표님이 하실 만한 질문 & 답변

예상 질문이렇게 답하세요
"이거 발주처 장비에서도 되는 거야?""네. 업계 표준 방식으로 만들어서 장비 종류와 상관없이 돌아갑니다. 설정 파일 하나만 바꾸면 되고, 설치 안내서까지 넘길 준비가 됐습니다."
"국산 반도체(NPU)는 언제 되나?""들어갈 자리는 이미 만들어놨습니다. 실물 칩이 확보되면 연결 부품(드라이버)만 붙이면 되는 구조입니다."

"해킹 걱정은 없나?""방금 보신 것처럼 로그인 없이는 차단됩니다. 정식 운영 때는 회사 계정 체계와 연동하는 설계까지 돼 있습니다."
