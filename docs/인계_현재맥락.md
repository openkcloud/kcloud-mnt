## 0. 한 줄 요약
목업(Next.js)이던 openKcloud 통합관리 포털을 **MSA 백엔드(FastAPI)로 실체화**하는 중.
동시에 **ETRI 관리망 테스트배드**에 AI 노트북(Kubeflow)·포털 DB·OpenStack 연동을 실제로 올리고 있다.

## 2. 아키텍처 핵심 결정
- **API Gateway = Istio(Envoy)** 경로 라우팅(코드 모듈 아님, 설정으로 제공). 각 모듈이 `/api/<도메인>` 직접 서빙. (oauth2-proxy 는 쓰지 않기로 함 — 아래 인증 방식)
- **인증 = Keycloak(OIDC).** 서버는 테스트배드·개발 모두 배포 완료(2026-10-12). 포털 연동은 설계 확정·개발 realm 설정 완료(2026-10-13), 구현은 다음 단계.
  - 방식: **Authorization Code + PKCE**(공개 클라이언트, 토큰은 브라우저 메모리) + **Keycloak 로그인 테마**(지금 `/login` 모양으로 제작 예정). 비밀번호를 포털이 받는 방식(ROPC, oc-cmp 방식)은 쓰지 않는다.
  - 백엔드(CORE·IAAS)가 요청마다 JWT 검증(서명·`iss`·`aud`·`exp`·종료 세션 `sid`). 역할(admin/user)은 **포털 DB** 기준으로 MNT-CORE 가 판정.

  | 환경 | 주소(토큰 발급자) | 배포 | DB |
  |---|---|---|---|
  | 테스트배드 | 관리: `https://keycloak.kcloud.etri:25443` / 로그인: `https://portal.kcloud.etri:25443/auth/realms/openkcloud_realm`(연동 적용 후) | helm 릴리스 `openkcloud-keycloak`(`openkcloud-mnt`, `keycloak-0~2`), 차트 `charts/infra/keycloak`, `quay.io/keycloak/keycloak:26.7.4` | `openkcloud-db` 의 DB `keycloak` · 스키마 `keycloak` |
  | 개발 | `http://keycloak.dev.okestro:8080/realms/openkcloud_realm` | Mac Mini(`172.30.1.200`) docker compose(colima) 1개, `infra/keycloak-dev` | Mac Mini PostgreSQL 의 DB `keycloak` · 스키마 `keycloak` |

  - realm `openkcloud_realm`(표시 이름 openKcloud): **개발은 설정 완료**, 테스트배드는 아직 `master` 만. 설정 원본 `charts/infra/keycloak/realm/openkcloud_realm.json`(적용법 `docs/포털_배포_가이드.md` 6장).
  - 클라이언트: **`mnt-app-client`**(브라우저용, 공개·PKCE S256) / **`mnt-core-client`**(CORE 서버용, 비밀형·서비스 계정 `manage-users`·`view-users`). API 토큰 `aud` 에 `mnt-core-client` 가 들어가도록 매퍼 설정 → 백엔드는 이 값으로 확인.
  - 사용자 프로필: 이름 전체를 `firstName` 에(필수), `email`·`lastName` 은 선택(포털 사용자 5명 모두 이메일 없음). 아이디 변경·회원가입·비밀번호 찾기 꺼짐, 한국어만.
  - 테스트배드 주소 설계: 로그인 내내 호스트 `portal.kcloud.etri` 유지 — 포털 VirtualService 가 `/auth/realms/openkcloud_realm/`·`/auth/resources/` 만 Keycloak 으로 보냄(차트 `gateway.keycloak.enabled`, 기본 꺼짐). `keycloak.kcloud.etri` 는 **관리자 전용**.
  - 진입 흐름(예정): `/` → `/auth/login`(포털 화면) → 세션 있으면 `/dashboard`, 없으면 Keycloak 로그인 화면.
  - 세션 결정: 브라우저를 껐다 켜도 유지(Remember me), 시간은 Keycloak 설정(미사용 30분·최대 10시간), 사용자 입력이 있을 때만 연장(자동 갱신 요청은 제외), 다른 탭 로그아웃·관리자 강제 로그아웃·다른 곳 로그인(동시 로그인 제한) 시 각각 안내 + 로그인 버튼, 강제 로그아웃은 Keycloak 백채널 통보로 서버가 즉시 거부. 상세는 메모리 `keycloak-login-decisions`.
  - 개발 주소는 접속 PC hosts 에 `172.30.1.200 keycloak.dev.okestro` 등록 필요. `.dev` 로 하지 않은 이유: 브라우저가 무조건 HTTPS 로 바꿔(HSTS) HTTP 로는 열리지 않는다.
  - 점검용 계정 `kc-test`(개발 realm). 개발 Keycloak 은 각자 PC 의 CORE 로 백채널 통보를 보낼 수 없다(강제 로그아웃 반영은 테스트배드에서 확인).
- **DB는 MNT-CORE만 소유.** IAAS/PAAS/OBS는 stateless — 상위 시스템(OpenStack/K8s/Prometheus) **라이브 조회**, 자원 실시간 상태는 DB에 저장 안 함(드리프트 방지).
- 설정은 전부 **env 주입**(12-factor): 파드 전환 시 비밀=Secret, 주소=ConfigMap. 프론트는 same-origin `/api/*`(게이트웨이 라우팅)로 백엔드 주소를 모르게.
- **자원 프로비저닝 = Temporal 워크플로.** 서버는 MNT-WORKFLOW(별도 파드, 저장소는 포털 DB 안 `temporal`·`temporal_visibility` 스키마), 워크플로 코드·DB 기록은 MNT-CORE 워커, OpenStack 작업은 MNT-IAAS 워커. CORE·IAAS 는 이 흐름에서 서로 직접 부르지 않고 Temporal 을 거친다. 상세 `MNT-WORKFLOW/README.md`.
- 상세: `docs/` + 메모리. (Keycloak 포털 연동은 **개발 realm 까지** — 백엔드 JWT 검증·프론트 로그인·테마·테스트배드 realm 은 미구축, 9장 4번)

## 4. DB (MNT-CORE 소유)
- **개발 DB**: Mac Mini Homebrew PostgreSQL 17.11 (`172.30.1.200:5432`, db `openkcloud_portal`, user `portal_user`). 비번은 `MNT-CORE/config.env`(gitignore).
- **운영 DB**: 관리 K8s에 CloudNativePG로 동일 PG 17.11 구축 완료 (ns `openkcloud-mnt`). `docs/포털DB_PostgreSQL_설치.md`.
- **Keycloak DB**: 포털 DB 와 별도 DB `keycloak`(스키마·계정 `keycloak`) — 테스트배드·개발 같은 구조. 준비 SQL `infra/keycloak-dev/keycloak_db.sql`, 상세 `docs/포털DB_PostgreSQL_설치.md` 8장.
- 스키마: `MNT-CORE/db/ddl.sql` + `seed.sql`. 테이블 명명규칙 `<도메인>_<단수>` snake_case (iam_/mnu_/cmn_/tkt_/mkt_/aud_).
  - 현재: `iam_user·iam_role·iam_user_role·mnu_menu·mnu_role_menu·cmn_code_group·cmn_code`
  - 공통코드: TKT_STATUS(pending/provisioning/completed/rejected)·TKT_TYPE·IAM_USER_STATUS (attr1=배지톤)
- ⚠️ PG15+ public 스키마 권한: `ALTER DATABASE .. OWNER TO portal_user` + `GRANT ALL ON SCHEMA public` 선행 필요.

## 5. 로컬 실행
```bash
# 프론트
cd MNT-APP && npm run dev            # http://localhost:3000  (dev는 webpack — package.json에 --webpack)

# 포털 코어 (DB 필요)
cd MNT-CORE && python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
cp config.env.example config.env     # DATABASE_URL 수정 (Mac Mini DB)
.venv/bin/uvicorn app.main:app --reload --port 8000
# 최초: psql 로 db/ddl.sql + db/seed.sql 적용

# IaaS (OpenStack 연동)
cd MNT-IAAS && python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
cp config.env.example config.env     # OS_AUTH_URL 등 (아래 6장)
.venv/bin/uvicorn app.main:app --reload --port 8001
```
```bash
# Temporal 서버(로컬 개발 서버) — 프로비저닝 워크플로용
brew install temporal                # 최초 1회
cd MNT-WORKFLOW && ./run-local.sh    # gRPC localhost:7233, 웹 화면 http://localhost:8233
# CORE·IAAS 의 config.env 에 TEMPORAL_API_BASE=localhost:7233 → uvicorn 기동 시 각 워커도 함께 시작
```
- 프론트가 바라보는 백엔드 주소: `NEXT_PUBLIC_CORE_API`(기본 localhost:8000), `NEXT_PUBLIC_IAAS_API`(기본 localhost:8001). 빈 값이면 same-origin(게이트웨이).
- Keycloak 연동용 CORE 설정(`MNT-CORE/config.env`, 백엔드 JWT 검증 구현 때부터 사용 — 지금 코드는 아직 읽지 않음):
  `KEYCLOAK_ISSUER=http://keycloak.dev.okestro:8080/realms/openkcloud_realm`, `KEYCLOAK_JWKS_URL=<ISSUER>/protocol/openid-connect/certs`, `KEYCLOAK_AUDIENCE=mnt-core-client`, `KEYCLOAK_CLIENT_ID=mnt-core-client`, `KEYCLOAK_CLIENT_SECRET`(Keycloak `mnt-core-client` → Credentials, git 금지).
- 프론트 로그인(예정)은 `localhost:3000`·`3001` 에서만 된다 — Keycloak 에 등록된 돌아올 주소·출처가 이 둘뿐이고, PKCE 는 HTTPS 또는 localhost 에서만 동작한다.
- ⚠️ **좀비 프로세스 주의**: 포트 충돌·Turbopack 패닉 시 `pkill -9 -f "next"; pkill -9 -f "uvicorn app.main"` 후 재실행.

## 6. 테스트배드 (ETRI 관리망)
- **SSH**: `ssh -p 25222 okes@210.114.95.51` (controller, 비root). master3는 root+kubectl.
- **외부 접속**: 맥북 → `210.114.95.50:25443`(NAT→istio-ingressgateway). `/etc/hosts`에 호스트 매핑 필요.
- ⚠️ **OpenStack API 도메인 변경(2026-10-02)**: `*.kcloud.cluster.local` → **`*.openstack.internal`**. 예: `https://keystone-api.openstack.internal:25443/v3` (HTTP/2 200 확인). 인증서는 사내 root CA(`kcloud-root-ca`) 정식 서명.
  - notebook/notebook-api는 여전히 `.kcloud.cluster.local`(우리가 만든 것).
  - MNT-IAAS `OS_AUTH_URL = https://keystone-api.openstack.internal:25443/v3`, 계정 `extadmin`(비번은 config.env), `OS_INSECURE=true`(CA 신뢰 전).
- **노트북(Kubeflow) 배포**: `docs/테스트배드_*.md` 3부작 (M1 프론트 ingress 노출 · M2 서비스클러스터+Kubeflow · M3 백엔드 연동). 서비스 클러스터는 Magnum/CAPI, Furiosa NPU 노드. 이미지 egress 불안정(미러 필요) 이슈 있음.

## 7. 주의/함정 (겪은 것)
- **openstacksdk 카탈로그 함정**: `conn.identity.projects()`는 Keystone 카탈로그의 내부 URL로 재호출 → 맥북서 도달불가 행. → `conn.session.get(os_auth_url+"/projects")`로 진입 URL 직접 질의로 우회(MNT-IAAS/app/routers/projects.py).
- **CNPG 이름충돌**: `kubectl get cluster`는 CAPI와 충돌 → `kubectl get clusters.postgresql.cnpg.io`.
- **Next 16 dev**: 기본 Turbopack이 이 프로젝트서 패닉 → `next dev --webpack`로 고정(빌드도 webpack).
- **리네이밍 시**: 테이블명 치환이 URL경로·라우트까지 오염 주의(테이블명과 API경로는 별개).

1. ~~MNT-CORE **로그인 API**(`/api/core/auth/login`)~~ → 포털 DB 비밀번호 로그인은 구현됨. Keycloak 연동(4번)이 끝나면 제거 예정
2. ~~**tkt_ 자원신청 테이블** 설계 + 워크플로우 API~~ → VM 신청·승인·프로비저닝(Temporal) 구현(2026-10-08). 테스트배드 mnt-workflow 배포 완료(2026-10-12). 남은 것: FIP 시험용 네트워크, 서비스 클러스터 신청
3. IaaS 다른 자원 실연동(가상서버·네트워크…) + 프로젝트 쿼터 enrich(Nova/Cinder limits)
4. **인증 스택 구축**: ~~Keycloak 서버 배포~~(2026-10-12) → ~~개발 realm·클라이언트 설정~~(2026-10-13) → 백엔드 JWT 검증(CORE·IAAS, 세션 기록·강제 로그아웃·동시 로그인) → 프론트 PKCE 로그인(`/auth/login`) → 로그인 테마 → 테스트배드 realm·`/auth` 경로 적용 → 기존 사용자 이관
   - 구현 전 결정 대기: 처음 보는 사용자 처리(자동 생성+역할 없음 추천), IAAS 1차 권한(로그인 확인+쓰기는 관리자), 동시 로그인 범위(브라우저 단위·관리자 포함 여부), 로그인 상태 유지 체크박스 강제 여부, 안내 문구 일부, 로그인 실패 잠금 기준
5. 모듈 **이미지 빌드 → Harbor(`harbor.io:7443`) push → 관리 K8s 파드 배포**
6. 노트북 M2/M3 이어가기(서비스 클러스터 이미지 미러)
