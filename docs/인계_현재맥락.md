## 0. 한 줄 요약
목업(Next.js)이던 openKcloud 통합관리 포털을 **MSA 백엔드(FastAPI)로 실체화**하는 중.
동시에 **ETRI 관리망 테스트배드**에 AI 노트북(Kubeflow)·포털 DB·OpenStack 연동을 실제로 올리고 있다.

## 1. 저장소 구조 (모노레포, 2026-10-01 개편)
```
openkcloud/                 (git: YunHoYoung-okestro/openkcloud, 브랜치 develop)
├── MNT-APP/      프론트 (Next.js 16, 기존 목업 v2 정렬본). ★ 실행은 여기서 npm run dev

├── MNT-PAAS/     K8s/Magnum 중개 FastAPI — 스캐폴드만
├── MNT-OBS/      Prometheus/Loki 중개 FastAPI — 스캐폴드만
├── MNT-WORKFLOW/ Temporal 서버(작업 장부) 배포 구성 — 우리 코드 없이 공식 이미지만 사용
├── infra/        인프라 구성 — keycloak-dev(개발 서버 Keycloak, docker compose)
```

- 모듈 네이밍 규칙: 대문자 `MNT-CORE`(문서) / 소문자 `mnt-core`(k8s·이미지).

## 2. 아키텍처 핵심 결정
- **API Gateway = Istio(Envoy) + oauth2-proxy** (코드 모듈 아님, 설정으로 제공). 각 모듈이 `/api/<도메인>` 직접 서빙.
- **인증 = Keycloak(OIDC).** 서버는 테스트배드·개발 모두 배포 완료(2026-10-12), 포털 연동은 예정. admin/user 구분은 검증된 JWT claim으로 엣지에서, 소유권 등 세밀 인가는 MNT-CORE가 DB로.

  | 환경 | 주소(토큰 발급자) | 배포 | DB |
  |---|---|---|---|
  | 테스트배드 | `https://keycloak.kcloud.etri:25443` | helm(`openkcloud-mnt`, `keycloak-0~2`), `quay.io/keycloak/keycloak:26.7.4` | `openkcloud-db` 의 DB `keycloak` · 스키마 `keycloak` |
  | 개발 | `http://keycloak.dev.okestro:8080` | Mac Mini(`172.30.1.200`) docker compose(colima) 1개, `infra/keycloak-dev` | Mac Mini PostgreSQL 의 DB `keycloak` · 스키마 `keycloak` |

  - 둘 다 설정 추가 없이 배포만 한 상태(realm 은 `master` 만, 클라이언트 설정 없음). 개발 주소는 접속 PC hosts 에 `172.30.1.200 keycloak.dev.okestro` 등록 필요.
  - 개발 주소를 `.dev` 로 하지 않은 이유: `.dev` 는 브라우저가 무조건 HTTPS 로 바꿔(HSTS) HTTP 로는 열리지 않는다.
- **DB는 MNT-CORE만 소유.** IAAS/PAAS/OBS는 stateless — 상위 시스템(OpenStack/K8s/Prometheus) **라이브 조회**, 자원 실시간 상태는 DB에 저장 안 함(드리프트 방지).
- 설정은 전부 **env 주입**(12-factor): 파드 전환 시 비밀=Secret, 주소=ConfigMap. 프론트는 same-origin `/api/*`(게이트웨이 라우팅)로 백엔드 주소를 모르게.
- **자원 프로비저닝 = Temporal 워크플로.** 서버는 MNT-WORKFLOW(별도 파드, 저장소는 포털 DB 안 `temporal`·`temporal_visibility` 스키마), 워크플로 코드·DB 기록은 MNT-CORE 워커, OpenStack 작업은 MNT-IAAS 워커. CORE·IAAS 는 이 흐름에서 서로 직접 부르지 않고 Temporal 을 거친다. 상세 `MNT-WORKFLOW/README.md`.
- 상세: `docs/` + 메모리. (Keycloak 은 서버만 배포 — realm·클라이언트 설정, oauth2-proxy·포털 연동은 **아직 미구축**, 선행 과제)

## 4. DB (MNT-CORE 소유)
- **개발 DB**: Mac Mini Homebrew PostgreSQL 17.11 (`172.30.1.200:5432`, db `openkcloud_portal`, user `portal_user`). 비번은 `MNT-CORE/config.env`(gitignore).
- **운영 DB**: 관리 K8s에 CloudNativePG로 동일 PG 17.11 구축 완료 (ns `openkcloud-mnt`). `docs/포털DB_PostgreSQL_설치.md`.
- **Keycloak DB**: 포털 DB 와 별도 DB `keycloak`(스키마·계정 `keycloak`) — 테스트배드·개발 같은 구조. 준비 SQL `infra/keycloak-dev/keycloak_db.sql`, 상세 `docs/포털DB_PostgreSQL_설치.md` 8장.
- 스키마: `MNT-CORE/db/ddl.sql` + `seed.sql`. 테이블 명명규칙 `<도메인>_<단수>` snake_case (iam_/mnu_/cmn_/tkt_/mkt_/aud_).
  - 현재: `iam_user·iam_role·iam_user_role·mnu_menu·mnu_role_menu·cmn_code_group·cmn_code`
  - 공통코드: TKT_STATUS(pending/provisioning/completed/rejected)·TKT_TYPE·IAM_USER_STATUS (attr1=배지톤)
- ⚠️ PG15+ public 스키마 권한: `ALTER DATABASE .. OWNER TO portal_user` + `GRANT ALL ON SCHEMA public` 선행 필요.

## 5. 로컬 실행
```bash
# 프론트
cd MNT-APP && npm run dev            # http://localhost:3000  (dev는 webpack — package.json에 --webpack)

# 포털 코어 (DB 필요)
cd MNT-CORE && python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
cp config.env.example config.env     # DATABASE_URL 수정 (Mac Mini DB)
.venv/bin/uvicorn app.main:app --reload --port 8000
# 최초: psql 로 db/ddl.sql + db/seed.sql 적용

# IaaS (OpenStack 연동)
cd MNT-IAAS && python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
cp config.env.example config.env     # OS_AUTH_URL 등 (아래 6장)
.venv/bin/uvicorn app.main:app --reload --port 8001
```
```bash
# Temporal 서버(로컬 개발 서버) — 프로비저닝 워크플로용
brew install temporal                # 최초 1회
cd MNT-WORKFLOW && ./run-local.sh    # gRPC localhost:7233, 웹 화면 http://localhost:8233
# CORE·IAAS 의 config.env 에 TEMPORAL_API_BASE=localhost:7233 → uvicorn 기동 시 각 워커도 함께 시작
```
- 프론트가 바라보는 백엔드 주소: `NEXT_PUBLIC_CORE_API`(기본 localhost:8000), `NEXT_PUBLIC_IAAS_API`(기본 localhost:8001). 빈 값이면 same-origin(게이트웨이).
- ⚠️ **좀비 프로세스 주의**: 포트 충돌·Turbopack 패닉 시 `pkill -9 -f "next"; pkill -9 -f "uvicorn app.main"` 후 재실행.

## 6. 테스트배드 (ETRI 관리망)
- **SSH**: `ssh -p 25222 okes@210.114.95.51` (controller, 비root). master3는 root+kubectl.
- **외부 접속**: 맥북 → `210.114.95.50:25443`(NAT→istio-ingressgateway). `/etc/hosts`에 호스트 매핑 필요.
- ⚠️ **OpenStack API 도메인 변경(2026-10-02)**: `*.kcloud.cluster.local` → **`*.openstack.internal`**. 예: `https://keystone-api.openstack.internal:25443/v3` (HTTP/2 200 확인). 인증서는 사내 root CA(`kcloud-root-ca`) 정식 서명.
  - notebook/notebook-api는 여전히 `.kcloud.cluster.local`(우리가 만든 것).
  - MNT-IAAS `OS_AUTH_URL = https://keystone-api.openstack.internal:25443/v3`, 계정 `extadmin`(비번은 config.env), `OS_INSECURE=true`(CA 신뢰 전).
- **노트북(Kubeflow) 배포**: `docs/테스트배드_*.md` 3부작 (M1 프론트 ingress 노출 · M2 서비스클러스터+Kubeflow · M3 백엔드 연동). 서비스 클러스터는 Magnum/CAPI, Furiosa NPU 노드. 이미지 egress 불안정(미러 필요) 이슈 있음.

## 7. 주의/함정 (겪은 것)
- **openstacksdk 카탈로그 함정**: `conn.identity.projects()`는 Keystone 카탈로그의 내부 URL로 재호출 → 맥북서 도달불가 행. → `conn.session.get(os_auth_url+"/projects")`로 진입 URL 직접 질의로 우회(MNT-IAAS/app/routers/projects.py).
- **CNPG 이름충돌**: `kubectl get cluster`는 CAPI와 충돌 → `kubectl get clusters.postgresql.cnpg.io`.
- **Next 16 dev**: 기본 Turbopack이 이 프로젝트서 패닉 → `next dev --webpack`로 고정(빌드도 webpack).
- **리네이밍 시**: 테이블명 치환이 URL경로·라우트까지 오염 주의(테이블명과 API경로는 별개).
