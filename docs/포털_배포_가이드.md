# 포털 배포 가이드 (관리 K8s)

openKcloud 포털(MNT-APP/CORE/IAAS/PAAS/OBS)과 Temporal 서버(MNT-WORKFLOW)를 관리 클러스터에 파드로 배포하는 절차. 인증 서버 Keycloak 은 6장.
빌드/배포는 **master3**(관리 클러스터 노드, amd64, Harbor 도달)에서 수행한다.

## 0. 환경 요약
| 항목 | 값 |
|---|---|
| 네임스페이스 | `openkcloud-mnt` |
| 레지스트리 | `harbor.io:7443/mnt` (admin push 가능) |
| 이미지 | `mnt-{app,core,iaas,paas,obs}:<git-sha>` |
| Temporal 서버 | `mnt-workflow` — 공식 이미지를 Harbor 로 옮겨 사용(`harbor.io:7443/mnt/mnt-workflow/temporalio/server`·`admin-tools` 1.31.3, `ui` 2.55.0, 빌드 없음). gRPC `mnt-workflow.openkcloud-mnt:7233` (CORE·IAAS 의 `TEMPORAL_API_BASE`) |
| Temporal 저장소 | 포털 DB 안의 스키마 `temporal`(계정 `temporal`) · `temporal_visibility`(계정 `temporal_view`) |
| 레포(master3) | `~/openkcloud` (브랜치 `develop`) |
| Helm 차트 | `charts/openkcloud-portal` (values.yaml = 관리 클러스터 값, `-f` 불필요) |
| DB | CNPG `openkcloud-db-rw.openkcloud-mnt:5432` / db `openkcloud_portal` / user `portal_user` (시크릿 `openkcloud-db-app-cred`) |
| OpenStack | `https://{service}-api.openstack.internal` **(내부 443. 25443은 외부 NAT 전용)** |
| 게이트웨이 | 기존 `istio-system/portal-gateway` 재사용, host `portal.kcloud.etri` · Temporal 웹 화면 `temporal.kcloud.etri` · Keycloak 관리 `keycloak.kcloud.etri` |
| Keycloak | helm 릴리스 `openkcloud-keycloak`, 차트 `charts/infra/keycloak`(keycloakx 7.3.2 + Istio 템플릿), 파드 `keycloak-0~2`, 서비스 `keycloak-http:80`. realm `openkcloud_realm` 원본 `charts/infra/keycloak/realm/openkcloud_realm.json` (6장) |
| 외부 접속 | `/etc/hosts`에 `210.114.95.50 portal.kcloud.etri temporal.kcloud.etri keycloak.kcloud.etri` → `https://portal.kcloud.etri:25443` · `https://temporal.kcloud.etri:25443` · `https://keycloak.kcloud.etri:25443/admin`(관리자 전용) |

## 1. 최초 1회 셋업 (이미 돼 있으면 건너뜀)

```bash
# (1) docker 그룹 (빌드용 소켓 권한)
sudo usermod -aG docker okes && newgrp docker

# (2) git 자격증명 (private 레포 pull). 토큰은 credential store 에 1회 저장
git config --global credential.helper store
printf 'https://<GITHUB_USER>:<PAT>@github.com\n' > ~/.git-credentials && chmod 600 ~/.git-credentials
#   ↳ okestro 조직은 PAT 생성 후 "Configure SSO → Authorize" 필수

# (3) helm 설치 확인
helm version || curl https://raw.githubusercontent.com/helm/helm/main/scripts/get-helm-3 | bash

# (4) 레포 클론
git clone https://github.com/YunHoYoung-okestro/openkcloud.git ~/openkcloud
cd ~/openkcloud && git checkout develop

# (5) Harbor pull 시크릿 (파드가 이미지 당길 때)
kubectl -n openkcloud-mnt get secret harbor-pull >/dev/null 2>&1 || \
kubectl -n openkcloud-mnt create secret docker-registry harbor-pull \
  --docker-server=harbor.io:7443 --docker-username=admin --docker-password='<HARBOR_PW>'

# (6) 앱 시크릿 — DB (비번은 CNPG 시크릿에서 동적 추출, 평문 저장 안 함)
PGPW=$(kubectl -n openkcloud-mnt get secret openkcloud-db-app-cred -o jsonpath='{.data.password}' | base64 -d)
#     KEYCLOAK_CLIENT_SECRET 은 테스트배드 Keycloak 의 mnt-core-client → Credentials(6.2 에서 Regenerate 한 값)
read -rsp 'mnt-core-client 비밀키: ' KCS; echo
kubectl -n openkcloud-mnt create secret generic mnt-core-secret \
  --from-literal=DATABASE_URL="postgresql+psycopg://portal_user:${PGPW}@openkcloud-db-rw.openkcloud-mnt:5432/openkcloud_portal" \
  --from-literal=KEYCLOAK_CLIENT_SECRET="${KCS}"
#   이미 있는 시크릿에 비밀키만 더할 때:
#   kubectl -n openkcloud-mnt patch secret mnt-core-secret -p "{\"stringData\":{\"KEYCLOAK_CLIENT_SECRET\":\"${KCS}\"}}"

# (7) 앱 시크릿 — OpenStack (extadmin 자격)
kubectl -n openkcloud-mnt create secret generic mnt-iaas-secret \
  --from-literal=OS_USERNAME='extadmin' --from-literal=OS_PASSWORD='<OS_PW>'

# (7-1) 앱 시크릿 — KCloud Monitor v2 (OBS) 관리 계정
kubectl -n openkcloud-mnt create secret generic mnt-obs-secret \
  --from-literal=MONITOR_USERNAME='admin' --from-literal=MONITOR_PASSWORD='<MONITOR_PW>'
# ⚠️ Monitor v2 는 master3 의 Docker 컨테이너(k8s 아님). MNT-OBS 파드가 닿는지 확인:
#   kubectl -n openkcloud-mnt run netcheck --rm -it --restart=Never --image=curlimages/curl -- \
#     curl -s -o /dev/null -w "%{http_code}\n" http://172.29.236.153:8000/api/v2/system/health
#   200 아니면 values.yaml 의 MONITOR_BASE_URL 을 Service/Endpoints 로 교체.

# (8) DB 스키마 1회 적용
kubectl -n openkcloud-mnt exec -i openkcloud-db-1 -- \
  env PGPASSWORD="${PGPW}" psql -h openkcloud-db-rw -U portal_user -d openkcloud_portal < MNT-CORE/db/ddl.sql
kubectl -n openkcloud-mnt exec -i openkcloud-db-1 -- \
  env PGPASSWORD="${PGPW}" psql -h openkcloud-db-rw -U portal_user -d openkcloud_portal < MNT-CORE/db/seed.sql
#     이어서 마이그레이션을 순서대로(이미 적용한 것은 건너뜀). 반드시 portal_user 로 — 새 테이블 소유자가 CORE 계정이어야 한다
for f in migration_v0.2_ticket.sql migration_v0.3_auth.sql; do
  kubectl -n openkcloud-mnt exec -i openkcloud-db-1 -- \
    env PGPASSWORD="${PGPW}" psql -v ON_ERROR_STOP=1 -h openkcloud-db-rw -U portal_user -d openkcloud_portal < MNT-CORE/db/$f
done

# (9) Temporal 저장소 1회 준비 — 계정 temporal·temporal_view, 스키마, btree_gin 확장 (슈퍼유저 postgres)
#     비밀번호는 입력받아 쓰고 파일·레포에 남기지 않는다(/ & 문자는 sed 치환이 깨지므로 쓰지 말 것).
#     테이블은 mnt-workflow 파드의 initContainer 가 기동 때 자동으로 설치·업그레이드한다.
read -rsp 'Temporal DB 비밀번호: ' TPW; echo
sed -e "s/<비밀번호1>/${TPW}/" -e "s/<비밀번호2>/${TPW}/" MNT-WORKFLOW/db/temporal_schema.sql | \
  kubectl -n openkcloud-mnt exec -i openkcloud-db-1 -- psql -U postgres -d openkcloud_portal

# (10) 앱 시크릿 — Temporal DB 계정 비밀번호(9 와 같은 값). 첫 helm 배포 때 차트가 만든다:
#      2장 helm 명령에 --set-string workflow.dbPassword="${TPW}" 를 붙인다(처음 배포·비밀번호 변경 때만).
#      직접 만들려면 아래처럼 만들고, 이때는 helm 에 dbPassword 를 넘기지 않는다(같은 이름 시크릿 충돌).
#   kubectl -n openkcloud-mnt create secret generic mnt-workflow-secret \
#     --from-literal=POSTGRES_PWD="${TPW}" --from-literal=VISIBILITY_POSTGRES_PWD="${TPW}"
```

## 2. 평상시 재배포 (코드 변경 반영)

```bash
cd ~/openkcloud
git pull                                   # 최신 develop

# 빌드 + Harbor 푸시 (태그=git sha 자동). 전체 또는 일부 모듈.
HARBOR_USER=admin HARBOR_PASS='<HARBOR_PW>' ./scripts/build-push.sh
#   일부만:  ./scripts/build-push.sh core app
#   빌드만:  PUSH=0 ./scripts/build-push.sh
#   → 끝에 TAG 와 helm 명령을 출력한다.

# 배포 (values.yaml 이 관리 클러스터 값이라 -f 불필요)
TAG=$(git rev-parse --short HEAD)
helm upgrade --install openkcloud-portal charts/openkcloud-portal \
  -n openkcloud-mnt --set global.image.tag=$TAG
#   처음 배포(또는 Temporal DB 비밀번호 변경) 때만 뒤에 추가 → 차트가 mnt-workflow-secret 생성:
#     --set-string workflow.dbPassword="${TPW}"      (비밀번호에 , 가 있으면 \, 로)
#   평소 재배포에는 빼도 된다 — 시크릿은 helm.sh/resource-policy: keep 이라 유지된다.
```

> `values.yaml`의 `global.image.tag`를 그 커밋 태그로 함께 올려두면 `--set` 없이도 된다. 지금은 `--set`으로 덮는 방식 권장(이미지와 배포 태그 일치 보장).

**Temporal 서버(mnt-workflow)**
- 공식 이미지라 빌드하지 않는다(`build-push.sh` 대상 아님). Harbor(`mnt/mnt-workflow/temporalio/*`)에 옮겨 둔 이미지를 `helm upgrade` 때 함께 배포한다.
- 배포 전략은 `Recreate`(옛 파드 종료 → 새 파드) — 몇 초 끊기지만 CORE·IAAS 워커는 자동으로 다시 연결하고, 진행 중인 워크플로는 기록된 지점부터 이어진다.
- 업그레이드마다 Job `mnt-workflow-namespace-<리비전>` 이 `default` 네임스페이스를 확인한다(없을 때만 생성).
- 버전 올리기는 `MNT-WORKFLOW/README.md` 참고(server·admin-tools 같은 버전, 마이너는 한 단계씩).
- ⚠️ mnt-iaas 워커는 재배포 때 실행 중인 OpenStack 작업(VM 생성 요청 등)을 최대 90초 기다리도록 돼 있지만,
  파드 종료 대기(`terminationGracePeriodSeconds`)가 기본 30초라 그 전에 끊길 수 있다 → **프로비저닝 진행 중에는 mnt-iaas 재배포를 피한다**(차트 반영 예정).

## 4. 트러블슈팅 (겪은 이슈)
| 증상 | 원인 | 조치 |
|---|---|---|
| `permission denied ... docker.sock` | okes 가 docker 그룹에 없음 | `sudo usermod -aG docker okes && newgrp docker` |
| `docker push` 인증서 에러 | Harbor 자체서명/사내 CA | `/etc/docker/daemon.json` 에 `{"insecure-registries":["harbor.io:7443"]}` 후 `systemctl restart docker` |
| `unknown field "spec"` / Service 누락 | 과거 템플릿 트림 버그(`8000---`) | 수정됨. 재발 시 `helm template`으로 문서 구분자 확인 |
| `invalid resource name ... '/'` | VS metadata.name 에 ns/name 사용 | 수정됨(이름=`openkcloud-portal`, 참조만 `istio-system/portal-gateway`) |
| iaas `"openstack":"error"` | OpenStack 포트/DNS | 내부는 **443**(25443 아님). CoreDNS가 `*-api.openstack.internal`→ingressgateway 해석하는지 확인 |
| core `"db":"error"` | DB 시크릿/스키마 | `mnt-core-secret` 존재·DATABASE_URL `+psycopg`, 스키마 적용 여부 확인 |
| 파드 `CreateContainerConfigError` | 시크릿 누락 | `mnt-core-secret`/`mnt-iaas-secret` 생성 |
| 파드 `ImagePullBackOff` | harbor-pull 시크릿/태그 | 시크릿 존재·이미지 태그 확인 |
| mnt-workflow `ImagePullBackOff` | Harbor 에 이미지가 없음 / harbor-pull 시크릿 | `mnt/mnt-workflow/temporalio/*` 에 3개 이미지·태그가 있는지, `harbor-pull` 시크릿 확인(옮기는 법 `MNT-WORKFLOW/README.md`) |
| mnt-workflow `Init:CrashLoopBackOff` | 스키마 설치(initContainer) 실패 | `kubectl -n openkcloud-mnt logs deploy/mnt-workflow -c schema` — (9) 계정·스키마·`btree_gin` 적용, `mnt-workflow-secret` 비밀번호 확인 |
| 프로비저닝 실패 "IAAS 워커가 작업을 가져가지 않습니다" | mnt-iaas 워커 미연결 | mnt-iaas 의 `TEMPORAL_API_BASE`, 로그의 `Temporal 워커 시작` 확인 |
| 설치 직후 `Namespace default is not found` | 네임스페이스 생성 후 반영까지 약 10초 | 잠시 뒤 자동 해소(워커는 5초마다 다시 연결) |

## 6. Keycloak (인증 서버)

`charts/infra/keycloak` 은 테스트배드에 설치돼 있던 릴리스 `openkcloud-keycloak` 의 차트·값을 저장소로 옮긴 것이다(2026-10-13, 원래 차트와 렌더링 결과가 같음 — 저장소 경로로 upgrade 해도 바뀌는 것이 없다). 포털 차트와 **별개 릴리스**라 2장 재배포로는 바뀌지 않는다.

### 6.1 재배포 (값·이미지를 바꿀 때만)
```bash
cd ~/openkcloud
helm upgrade -n openkcloud-mnt openkcloud-keycloak charts/infra/keycloak \
  -f charts/infra/keycloak/values-openkcloud.yaml
kubectl -n openkcloud-mnt rollout status sts/keycloak      # 파드 3개가 하나씩 교체된다(PDB maxUnavailable 1)
```
- `values-openkcloud.yaml` 에는 Keycloak DB·첫 관리자 비밀번호가 들어 있다(비공개 저장소 전제로 그대로 커밋). 저장소 밖으로 공유하지 않는다.
- 로그인 테마를 넣을 때 이미지를 Harbor 이미지로 바꾼다(예정 — `image.repository`·`tag`, `imagePullSecrets: harbor-pull`).

### 6.2 realm 적용 (포털 연동 적용 때 1회)
개발 Keycloak 에서 설정해 내보낸 `charts/infra/keycloak/realm/openkcloud_realm.json` 을 가져온 뒤 테스트배드 값으로 바꾼다.
1. `https://keycloak.kcloud.etri:25443/admin` → realm 목록 → **Create realm** → Resource file 에 위 파일 → Create
2. 아래 값을 바꾼다.

| 위치 | 파일 값(개발) | 테스트배드 |
|---|---|---|
| Realm settings → General → Frontend URL | 없음 | `https://portal.kcloud.etri:25443/auth` |
| Clients → `mnt-app-client` → Valid redirect URIs · Valid post logout redirect URIs | `http://localhost:3000/*`, `http://localhost:3001/*` | `https://portal.kcloud.etri:25443/*` |
| Clients → `mnt-app-client` → Web origins | `http://localhost:3000`, `http://localhost:3001` | `https://portal.kcloud.etri:25443` (경로·끝 `/` 없이) |
| Clients → `mnt-app-client` → Logout settings → Backchannel logout URL | 비움 | `http://mnt-core.openkcloud-mnt.svc.cluster.local/api/core/auth/backchannel-logout` (CORE 배포 후, 6.4) |
| Clients → `mnt-core-client` → Credentials | 가려진 값(`**********`) | **Regenerate** — 가져온 값을 그대로 쓰지 않는다. 새 값은 `mnt-core-secret` 에 넣는다(1장 (6)) |

- 사용자를 만들 때 이름(First name)은 필수, 이메일·성은 선택이다(사용자 프로필 설정).
- realm 설정을 바꿀 때는 **개발 Keycloak 에서 고친 뒤** Realm settings → Action → **Partial export**(groups·roles, clients 포함) → 파일을 덮어써 커밋한다. 비밀키는 내보낼 때 가려진다.

CORE 설정값(주소는 `charts/openkcloud-portal/values.yaml` 의 core env 에 들어 있음, 비밀키만 Secret):

| 키 | 개발(`MNT-CORE/config.env`) | 테스트배드 |
|---|---|---|
| `KEYCLOAK_ISSUER` | `http://keycloak.dev.okestro:8080/realms/openkcloud_realm` | `https://portal.kcloud.etri:25443/auth/realms/openkcloud_realm` |
| `KEYCLOAK_JWKS_URL` | `<ISSUER>/protocol/openid-connect/certs` | `http://keycloak-http.openkcloud-mnt.svc.cluster.local/realms/openkcloud_realm/protocol/openid-connect/certs` (클러스터 내부 주소 — 25443 은 외부 NAT 전용) |
| `KEYCLOAK_AUDIENCE` · `KEYCLOAK_CLIENT_ID` | `mnt-core-client` | `mnt-core-client` |
| `KEYCLOAK_INTERNAL_URL` | (비움 — ISSUER 사용) | `http://keycloak-http.openkcloud-mnt.svc.cluster.local/realms/openkcloud_realm` (토큰 발급·관리 API) |
| `KEYCLOAK_CLIENT_SECRET` | config.env(git 제외) | Secret `mnt-core-secret`(1장 (6)) |
| `SESSION_SINGLE_LOGIN` | `false`(여러 개발자가 `admin` 공유) | 기본값 `true` — 동시 로그인 제한(브라우저 단위, 관리자 포함) |

### 6.3 포털 주소로 로그인 경로 열기
포털 VirtualService 에 `/auth/realms/openkcloud_realm/`·`/auth/resources/` → Keycloak 규칙을 넣는다(`/auth` 를 떼고 `keycloak-http:80` 으로 전달, `keycloak-vs` 와 같은 `X-Forwarded-*` 헤더). `/auth/login` 은 포털 화면이고, 관리 화면·master realm 은 포털 주소로 열지 않는다(`keycloak.kcloud.etri` 로만).
- 6.2 의 Frontend URL 을 먼저 지정한 뒤, `charts/openkcloud-portal/values.yaml` 의 `gateway.keycloak.enabled` 를 `true` 로 바꿔 커밋하고 2장 명령으로 배포한다.
  ⚠️ `--set gateway.keycloak.enabled=true` 로 한 번만 켜면 다음 평상시 배포(2장 명령) 때 꺼져서 로그인이 끊긴다.
- 확인(포털에 접속하는 PC 에서):
```bash
curl -sk https://portal.kcloud.etri:25443/auth/realms/openkcloud_realm/.well-known/openid-configuration | jq -r .issuer
#   → https://portal.kcloud.etri:25443/auth/realms/openkcloud_realm
curl -sk https://portal.kcloud.etri:25443/auth/realms/master/.well-known/openid-configuration | head -c 100; echo
#   → Keycloak JSON 이 아니라 포털(nginx) 응답이어야 한다
```

### 6.4 포털 로그인 연동 적용 순서 (테스트배드, 처음 1회)
CORE·IAAS 는 새 이미지부터 **모든 API 에 토큰을 요구**하고, 프론트는 Keycloak 으로 로그인한다. 아래가 다 갖춰진 뒤 새 이미지를 배포한다.
1. 6.2 — realm 가져오기, 테스트배드 값으로 변경, `mnt-core-client` 비밀키 Regenerate
2. 1장 (6) — `mnt-core-secret` 에 `KEYCLOAK_CLIENT_SECRET` 추가
3. 1장 (8) — `migration_v0.3_auth.sql` 적용(portal_user)
4. Keycloak 에 포털 사용자 등록 — 포털 DB(`iam_user`)와 **같은 아이디**(소문자), First name 에 이름. 포털 DB 에 없는 사용자는 로그인해도 403
5. 6.3 — `gateway.keycloak.enabled: true` 커밋 후 2장 명령으로 배포(`build-push.sh` 가 `build:gateway` 로 프론트를 빌드 — Keycloak 주소는 같은 출처 `/auth`)
6. 6.2 표의 Backchannel logout URL 지정(CORE 배포 후) — 관리 화면에서 세션을 끊으면 5초 안에 화면에 반영
7. 확인: `https://portal.kcloud.etri:25443` → Keycloak 로그인(주소창 호스트 유지) → 대시보드. 관리자·사용자 화면, 두 탭 로그아웃, 관리 화면 세션 끊기

### 6.5 Keycloak 트러블슈팅 (개발 realm 설정·연동 때 겪은 것)
| 증상 | 원인 | 조치 |
|---|---|---|
| 브라우저 토큰 요청이 `403 {"error":"Invalid origin"}` | Web origins 에 경로(`/*`)를 붙임, 또는 Save 를 안 누름 | 출처만(`http://localhost:3000`) 적고 Save |
| 로그인 직후 "계정 정보 업데이트" 화면(VERIFY_PROFILE) | 사용자 프로필 필수 항목이 비어 있음 | 계정에 이름 입력(현재 `firstName` 만 필수) |
| "클라이언트를 찾을 수 없습니다" | Client ID 를 바꿈 | Client ID 는 앱 설정과 묶여 있다. 보이는 이름은 Name 칸에 |
| `{"error":"Realm does not exist"}` | realm 이름(ID)을 바꿈 | realm 이름은 발급자 주소·포털 경로(`/auth/realms/openkcloud_realm/`)와 묶여 있다. 보이는 이름은 Display name 에 |
| 로그인 화면이 영어 | 국제화 꺼짐 | Realm settings → Localization → 한국어 기본 |
| CORE 응답 503 `AUTH_NOT_CONFIGURED` | `KEYCLOAK_ISSUER`·`KEYCLOAK_JWKS_URL` 없음 | core env(values.yaml)·로컬 config.env 확인 |
| CORE 500 `permission denied for table iam_user_session` | 마이그레이션을 슈퍼유저로 적용해 테이블 소유자가 다름 | `ALTER TABLE iam_user_session OWNER TO portal_user;` (v0.3 파일에는 반영됨) |
| 로그인 후 "포털에 등록되지 않은 계정입니다…" | Keycloak 에만 있고 포털 DB 에 없는 아이디 | 포털 DB 사용자와 같은 아이디로 맞춤 |
| 다른 PC 에서 `http://IP:3000` 으로 로그인 안 됨 | PKCE 는 HTTPS·localhost 에서만 | 각자 localhost 에서, 또는 테스트배드(HTTPS)에서 |

> 시크릿(DB/OpenStack 비번, Harbor 비번)은 **문서·레포에 평문 저장 금지**. 위 명령의 `<...>`는 그때 입력하거나 클러스터 시크릿에서 추출한다. 추후 SealedSecrets 전환 예정. (예외: `charts/infra/keycloak/values-openkcloud.yaml` 은 테스트배드 배포값 그대로 비밀번호 포함 — 2026-10-13 결정)
