# 포털 배포 가이드 (관리 K8s)

openKcloud 포털(MNT-APP/CORE/IAAS/PAAS/OBS)을 관리 클러스터에 파드로 배포하는 절차.
빌드/배포는 **master3**(관리 클러스터 노드, amd64, Harbor 도달)에서 수행한다.

## 0. 환경 요약
| 항목 | 값 |
|---|---|
| 네임스페이스 | `openkcloud-mnt` |
| 레지스트리 | `harbor.io:7443/mnt` (admin push 가능) |
| 이미지 | `mnt-{app,core,iaas,paas,obs}:<git-sha>` |
| 레포(master3) | `~/openkcloud` (브랜치 `develop`) |
| Helm 차트 | `charts/openkcloud-portal` (values.yaml = 관리 클러스터 값, `-f` 불필요) |
| DB | CNPG `openkcloud-db-rw.openkcloud-mnt:5432` / db `openkcloud_portal` / user `portal_user` (시크릿 `openkcloud-db-app-cred`) |
| OpenStack | `https://{service}-api.openstack.internal` **(내부 443. 25443은 외부 NAT 전용)** |
| 게이트웨이 | 기존 `istio-system/portal-gateway` 재사용, host `portal.kcloud.etri` |
| 외부 접속 | `/etc/hosts`에 `210.114.95.50 portal.kcloud.etri` → `https://portal.kcloud.etri:25443` |

## 1. 최초 1회 셋업 (이미 돼 있으면 건너뜀)

```bash
# (1) docker 그룹 (빌드용 소켓 권한)
sudo usermod -aG docker okes && newgrp docker

# (2) git 자격증명 (private 레포 pull). 토큰은 credential store 에 1회 저장
git config --global credential.helper store
printf 'https://<GITHUB_USER>:<PAT>@github.com\n' > ~/.git-credentials && chmod 600 ~/.git-credentials
#   ↳ okestro 조직은 PAT 생성 후 "Configure SSO → Authorize" 필수

# (3) helm 설치 확인
helm version || curl https://raw.githubusercontent.com/helm/helm/main/scripts/get-helm-3 | bash

# (4) 레포 클론
git clone https://github.com/YunHoYoung-okestro/openkcloud.git ~/openkcloud
cd ~/openkcloud && git checkout develop

# (5) Harbor pull 시크릿 (파드가 이미지 당길 때)
kubectl -n openkcloud-mnt get secret harbor-pull >/dev/null 2>&1 || \
kubectl -n openkcloud-mnt create secret docker-registry harbor-pull \
  --docker-server=harbor.io:7443 --docker-username=admin --docker-password='<HARBOR_PW>'

# (6) 앱 시크릿 — DB (비번은 CNPG 시크릿에서 동적 추출, 평문 저장 안 함)
PGPW=$(kubectl -n openkcloud-mnt get secret openkcloud-db-app-cred -o jsonpath='{.data.password}' | base64 -d)
kubectl -n openkcloud-mnt create secret generic mnt-core-secret \
  --from-literal=DATABASE_URL="postgresql+psycopg://portal_user:${PGPW}@openkcloud-db-rw.openkcloud-mnt:5432/openkcloud_portal"

# (7) 앱 시크릿 — OpenStack (extadmin 자격)
kubectl -n openkcloud-mnt create secret generic mnt-iaas-secret \
  --from-literal=OS_USERNAME='extadmin' --from-literal=OS_PASSWORD='<OS_PW>'

# (7-1) 앱 시크릿 — KCloud Monitor v2 (OBS) 관리 계정
kubectl -n openkcloud-mnt create secret generic mnt-obs-secret \
  --from-literal=MONITOR_USERNAME='admin' --from-literal=MONITOR_PASSWORD='<MONITOR_PW>'
# ⚠️ Monitor v2 는 master3 의 Docker 컨테이너(k8s 아님). MNT-OBS 파드가 닿는지 확인:
#   kubectl -n openkcloud-mnt run netcheck --rm -it --restart=Never --image=curlimages/curl -- \
#     curl -s -o /dev/null -w "%{http_code}\n" http://172.29.236.153:8000/api/v2/system/health
#   200 아니면 values.yaml 의 MONITOR_BASE_URL 을 Service/Endpoints 로 교체.

# (8) DB 스키마 1회 적용
kubectl -n openkcloud-mnt exec -i openkcloud-db-1 -- \
  env PGPASSWORD="${PGPW}" psql -h openkcloud-db-rw -U portal_user -d openkcloud_portal < MNT-CORE/db/ddl.sql
kubectl -n openkcloud-mnt exec -i openkcloud-db-1 -- \
  env PGPASSWORD="${PGPW}" psql -h openkcloud-db-rw -U portal_user -d openkcloud_portal < MNT-CORE/db/seed.sql
```

## 2. 평상시 재배포 (코드 변경 반영)

```bash
cd ~/openkcloud
git pull                                   # 최신 develop

# 빌드 + Harbor 푸시 (태그=git sha 자동). 전체 또는 일부 모듈.
HARBOR_USER=admin HARBOR_PASS='<HARBOR_PW>' ./scripts/build-push.sh
#   일부만:  ./scripts/build-push.sh core app
#   빌드만:  PUSH=0 ./scripts/build-push.sh
#   → 끝에 TAG 와 helm 명령을 출력한다.

# 배포 (values.yaml 이 관리 클러스터 값이라 -f 불필요)
TAG=$(git rev-parse --short HEAD)
helm upgrade --install openkcloud-portal charts/openkcloud-portal \
  -n openkcloud-mnt --set global.image.tag=$TAG
```

> `values.yaml`의 `global.image.tag`를 그 커밋 태그로 함께 올려두면 `--set` 없이도 된다. 지금은 `--set`으로 덮는 방식 권장(이미지와 배포 태그 일치 보장).

## 3. 검증

```bash
kubectl -n openkcloud-mnt get pods           # mnt-* 5개 Running 1/1
kubectl -n openkcloud-mnt get svc | grep mnt- # 서비스 5개 (app/core/iaas/paas/obs)
kubectl -n openkcloud-mnt get vs             # openkcloud-portal → portal.kcloud.etri

# 내부 헬스 (DB/OpenStack 연결)
kubectl -n openkcloud-mnt exec deploy/mnt-core -- wget -qO- localhost:8000/healthz; echo  # "db":"ok"
kubectl -n openkcloud-mnt exec deploy/mnt-iaas -- wget -qO- localhost:8000/healthz; echo  # "openstack":"ok"
```
브라우저: `https://portal.kcloud.etri:25443` → 메뉴(`/api/core`, DB)·IaaS(`/api/iaas`, OpenStack) 실데이터 확인.

## 4. 트러블슈팅 (겪은 이슈)
| 증상 | 원인 | 조치 |
|---|---|---|
| `permission denied ... docker.sock` | okes 가 docker 그룹에 없음 | `sudo usermod -aG docker okes && newgrp docker` |
| `docker push` 인증서 에러 | Harbor 자체서명/사내 CA | `/etc/docker/daemon.json` 에 `{"insecure-registries":["harbor.io:7443"]}` 후 `systemctl restart docker` |
| `unknown field "spec"` / Service 누락 | 과거 템플릿 트림 버그(`8000---`) | 수정됨. 재발 시 `helm template`으로 문서 구분자 확인 |
| `invalid resource name ... '/'` | VS metadata.name 에 ns/name 사용 | 수정됨(이름=`openkcloud-portal`, 참조만 `istio-system/portal-gateway`) |
| iaas `"openstack":"error"` | OpenStack 포트/DNS | 내부는 **443**(25443 아님). CoreDNS가 `*-api.openstack.internal`→ingressgateway 해석하는지 확인 |
| core `"db":"error"` | DB 시크릿/스키마 | `mnt-core-secret` 존재·DATABASE_URL `+psycopg`, 스키마 적용 여부 확인 |
| 파드 `CreateContainerConfigError` | 시크릿 누락 | `mnt-core-secret`/`mnt-iaas-secret` 생성 |
| 파드 `ImagePullBackOff` | harbor-pull 시크릿/태그 | 시크릿 존재·이미지 태그 확인 |

## 5. 롤백 / 태그 관리
```bash
helm -n openkcloud-mnt history openkcloud-portal      # 리비전 이력
helm -n openkcloud-mnt rollback openkcloud-portal <REVISION>
# 특정 태그로 재배포
helm upgrade openkcloud-portal charts/openkcloud-portal -n openkcloud-mnt --set global.image.tag=<git-sha>
```

> 시크릿(DB/OpenStack 비번, Harbor 비번)은 **문서·레포에 평문 저장 금지**. 위 명령의 `<...>`는 그때 입력하거나 클러스터 시크릿에서 추출한다. 추후 SealedSecrets 전환 예정.
